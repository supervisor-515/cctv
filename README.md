# CCTV 근무표 자동배정

부대 CCTV 근무표를 자동으로 편성하는 오프라인 웹앱입니다. 별도 서버 없이 동작하며 모든 데이터는 브라우저 localStorage에 보관됩니다.

## 실행

`index.html`을 웹 브라우저로 열면 즉시 실행됩니다 (`engine.js`가 같은 폴더에 있어야 합니다).
별도 빌드나 설치 과정이 필요 없습니다.

## 앱 설치 (PWA)

설치형 웹앱(PWA)을 지원하여 모바일 및 PC 홈 화면/시작 메뉴에 앱으로 등록할 수 있습니다.

- **조건**: `http://`, `https://` 또는 `localhost` 환경에서 접속해야 합니다. `file://` 경로로 열면 설치 및 오프라인 캐시가 동작하지 않습니다. 간이 실행 시 터미널에서 `python3 -m http.server` 실행 후 안내되는 주소로 접속하십시오.
- **설치 방법**:
  - Android (Chrome/Edge): 주소창의 설치 아이콘 또는 브라우저 메뉴 → *앱 설치 / 홈 화면에 추가*
  - iOS (Safari): 공유 버튼 → *홈 화면에 추가*
  - 데스크톱 (Chrome/Edge): 주소창 우측 *설치* 아이콘
- **오프라인 지원**: 최초 1회 접속 후 서비스 워커(`sw.js`)가 앱 셸을 캐시하여 네트워크 연결 없이도 실행됩니다. 온라인 상태에서는 항상 최신 버전을 수신합니다 (Network-First).
- 앱 아이콘, 이름, 테마 색상은 `manifest.webmanifest`에서 설정합니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | UI 마크업, 화면 제어, localStorage 입출력. 화면 표시 및 사용자 인터랙션 처리. |
| `engine.js` | 배정 알고리즘 엔진, 통계 계산, 무결성 검증. DOM 비의존 구조로 Node.js `require()` 테스트 지원. |
| `sync.js` | Firebase 기반 서버 동기화 모듈 (선택 기능). 관리자 편집 업로드 및 구성원 실시간 열람 지원. |
| `firebase-config.sample.js` | 동기화 설정 템플릿 파일 — `firebase-config.js`로 복사하여 사용. |
| `FIREBASE_SETUP.md` | Firebase 동기화 설정 매뉴얼 (프로젝트 생성, 계정 발급, 보안 규칙, 앱 연동). |
| `manifest.webmanifest` | PWA 매니페스트 (앱 명칭, 테마 색상, 아이콘 규격 등 홈 화면 설치 정보 정의). |
| `sw.js` | 서비스 워커 스크립트. 앱 리소스 캐싱을 통한 오프라인 구동 및 PWA 설치 지원. |
| `icon-*.png` | 앱 아이콘 이미지 세트 (192/512 일반·maskable, Apple 터치 180, 파비콘 32). |
| `test/engine.test.js` | 엔진 로직 검증 회귀 테스트 (`node --test`). |

## 배정 규칙

**하드 제약 (절대 위반 불가)**
- 인접 슬롯 연속근무 금지 (고정 슬롯 포함)
- 전날 야간 근무자의 익일 아침(06:30, 07:30, 08:30) 근무 배정 금지
- 당일 야간 번초 중복 배정 금지 (1인 1일 1야간 번초 제한)
- 열외 지정자(주간, 야간, 전체, 시간대) 해당 슬롯 배정 금지

**시간대 열외**
[생성] 탭에서 특정 인원의 시간대 열외를 당일 단위로 지정할 수 있습니다.
기본 밴드는 **아침(06:30~08:30), 오전(09:30~11:30), 오후(12:30~16:30), 야간(1~4번초)** 4개 구간이며, '세부' 항목을 펼쳐 주간 11개 슬롯 및 번초 4개를 개별 지정할 수 있습니다. 저녁 구간(17:30~21:30)은 역할 고정 칸이므로 열외 대상이 아닙니다.
- **밥교대**: 밥교대 근무 시간(07:00~08:30, 13:00~15:00, 17:00~18:30)과 겹치는 슬롯이 하나라도 열외되면 후보에서 제외됩니다. 아침·오후 열외자는 제외되며, **오전(09:30~11:30)만 열외된 인원은 밥교대 배정 가능**합니다.
- **밥교대 7일 간격 유지**: 밥교대 투입 후 최소 7일간 재배정되지 않습니다 (해당 일자 전후 6일 내 기편성 표에 밥교대 이력이 있으면 후보 제외). 가용 인원이 없는 경우에만 완화 적용됩니다.
- **17:00 순찰**: 순찰 시간과 겹치는 16:30 슬롯 열외자만 후보에서 제외됩니다.
- **분모 계산**: 부분 열외자는 당일 분모(근무 대상 일수)에 유지됩니다. 종일 열외 시에만 '분모에서 제외'를 설정할 수 있습니다.
- 부분 열외자는 분모가 유지되므로 해당 시간대 배정률이 낮아져 추후 우선 편성됩니다.
- 데이터는 `dayEx`(주간 전체), `nightEx`(야간 전체), `bothEx`(종일+분모제외), `slotEx`(부분)로 구분 저장됩니다. [달력 · 일정] 탭의 사전등록 및 기간 일괄 생성은 주간/종일 열외만 처리합니다.

**유조차 운전병(정)**
해당 주간(월~일) CCTV 일반 근무에서 열외되나, 완전 열외는 아닙니다.
금요일 야간 1개 번초와 토·일·**휴일**(공휴일, 지정 휴무일, 직장 휴무일) 오후 1개 슬롯(12:30 이후)을 의무 수행합니다.
번초와 시간대는 본인 누적 횟수가 가장 적은 슬롯으로 자동 배정되며, 금요일이 휴일인 경우 야간 대신 오후 1개 슬롯을 수행합니다.
유조차 운행 보상 차원에서 해당 근무는 분모(근무 대상 일수)에 산입되지 않고 평균 근무시간과 배정률만 누적됩니다.
당일 당직·상황병 역할이 지정된 경우 역할 근무를 우선 수행하며, 유조차 할당 근무(오후 슬롯 또는 금요일 야간)는 추가 배정되지 않습니다 (당일 역할자 및 전날 당직/상황병으로 인한 근무취침 시 오후 슬롯 제외, 전날·당일·다음날 역할 지정 시 금요일 야간 번초 제외).
대체자(부)는 해당 기간 CCTV 전체 열외입니다.
[근무표 생성] 탭의 열외 목록에 해당 규칙이 표시됩니다. 월~목 종일, 금요일 야간 번초 제외 전 슬롯, 토·일·휴일 12:30~16:30 제외 전 슬롯이 **잠금 열외**(7일 분모 제외) 처리되며, '직장 휴무일' 설정 변경 시 즉시 반영됩니다. 허용 구간 내 특정 슬롯을 추가 열외로 지정하면 자동 배정 대상에서 제외됩니다.

**추가배식조**
[근무자 관리]에서 [추가배식조 가능]으로 설정된 인원 중 **평일(주말·공휴일·휴무일 제외)마다 1명**이 자동 편성됩니다.
06:30 배정과 동일하게 순번제로 운영됩니다: ① 추가배식조 배정률(수행 횟수 ÷ 설정 후 평일 대상 일수) 낮은 순 → ② 최근 수행일이 오래된 순. 동일 인원의 이틀 연속 배정은 금지됩니다 (대체 후보 부재 시 예외).
D-1일차 근무표 생성 시 '다음날 추가배식조'로 선발되어 **D-1일차 야간 번초에서 제외**되며, D일차 근무표에서는 **당일 CCTV 전 근무(주간, 순찰, 저녁, 야간, 밥교대) 열외 및 분모(근무일수) 제외** 처리됩니다.
D일차 당직·상황병, D-1일차 및 D+1일차 당직·상황병(D일차 저녁 고정), 당일 휴가·열외·유조차·배식조 대상자는 후보에서 제외됩니다. 가용 후보가 없으면 미배정 처리 후 경고가 표시됩니다.
[생성] 탭 역할 표의 '추가배식' 행에서 당일(전날 표 연동) 및 다음날(자동/없음/수동 지정)을 변경할 수 있습니다.
**과거 기록**은 [근무표 › 편집]에서 해당 일자 '추가배식조' 카드에 인원을 직접 지정하여 입력할 수 있으며, 순번 계산에 정상 반영됩니다. 기능 도입 이전의 근무표는 추가배식조가 없는 정상 표로 취급하여 경고를 발생시키지 않습니다.
관리자 화면에서는 당직사관·사령 위치에 추가배식조(당일·다음날)가 표시되며, 달력, 내 근무, 배정 이유, 카운트 탭에서도 집계 내역을 확인할 수 있습니다.

**관제병**
[근무자 관리]에서 [관제병] 속성을 부여합니다. 기존 구분(신병, 당직, 상황병 등)은 유지되며, 근무표 생성 시 다음 규칙이 자동 적용됩니다:
① 매주 **토요일(휴일 토요일 포함) 07:30~14:30 슬롯** 및 당일 밥교대 제외 (06:30, 15:30, 16:30, 저녁, 야간 정상 편성 가능)
② **운항병이 상황병인 날(D)** 기준, D-1일차 및 D일차 근무표의 **야간 번초** 편성 제외 (D-1일차 표의 '다음날 상황병', D일차 표의 '상황병' 기준 판단)
규칙은 생성된 표의 시간대 열외 및 야간 열외 데이터로 보관되므로 수동 편집 시 점검에 반영됩니다.

**배식조**
[달력 › 일정 추가 › 배식조]. 선택 날짜가 포함된 주간(월~일) 전체로 등록됩니다.
해당 주간 내내 CCTV 근무에서 **전체 열외**됩니다 (휴가와 동일하게 분모 제외, 부분 근무 없음). 동일 주간에 복수 인원 등록이 가능하며, 동일 인원의 중복 등록은 하나로 병합됩니다. 당직·상황병 역할이 지정된 날은 역할 근무를 정상 수행합니다.

**완화 사다리 (단계적 완화 규칙)**
가용 인원이 부족한 경우 다음 순서로 규칙을 완화하여 편성합니다:
1. tier 1: 제약 위반 없음 (1인 1일 1슬롯 원칙)
2. tier 2: 당일 중복 투입 허용 (하루 2회 이상 근무)
3. tier 3: 야간 2일 연속 투입 허용
4. tier 4: 야간 3일 연속 투입 허용 (인원 부족으로 공백 발생 시에만 제한적 적용)
5. tier 5: 부분 편성 — 하드 제약을 충족할 수 없는 슬롯은 미배정 공란으로 유지

**공정성 배정**
누적 평균 근무시간과 그룹/슬롯/번초/야간/밥교대/순찰 배정률을 종합 가중합산한 점수가 낮은 인원부터 우선 배정합니다 ([더보기 › 기본 설정]에서 가중치 조정 가능). 주간 슬롯은 **당일과 동일한 그룹(월화목/수/금/토일) 내 해당 슬롯 배정률**이 낮은 인원부터 우선 배정됩니다. 백트래킹(MRV) 알고리즘으로 최적해를 도출한 후 1-opt 및 2-opt 국소 최적화 교환을 수행합니다. 신병은 일일 2개 슬롯 기본 배정 기준으로 산정됩니다.

**06:30 순번제**
06:30 슬롯은 점수 가중치 경쟁 없이 신병과 비신병이 단일 순번제로 순환합니다. **06:30 배정률**(06:30 수행 횟수 ÷ 가용 근무일수)이 가장 낮은 인원이 1순위이며, 동률 시 최종 06:30 수행일이 가장 오래된 인원 순으로 배정됩니다. 단순 누적 횟수가 아닌 배정률 기준으로 비교하므로 전입, 휴가 복귀, 신병→역할 전환 직후 특정 인원에게 몰리지 않습니다. 배정률은 카운트 초기화와 무관하게 전 기간 기록으로 산출합니다.

**난수 비사용 (결정론적 배정)**
알고리즘 내에 난수를 사용하지 않으므로 동일한 입력 조건에서는 항상 동일한 근무표가 생성됩니다. 모든 평가 기준이 동점일 경우 해당 슬롯(번초, 순찰)의 **최종 수행일이 가장 오래된 인원**을 우선 배정합니다. 최종 수행일마저 동일할 경우 근무자 등록 목록 순서를 따릅니다.

누적 횟수 지표는 **각자의 분모(가용 근무일수)로 나눈 비율로 환산하여 비교**합니다. 단순 누적 횟수로 비교할 경우 분모가 적은 인원(역할 전환으로 초기화된 인원, 중도 전입자, 장기 휴가자)이 누적치를 맞추기 위해 연속 과편성되는 현상을 방지합니다. 표본 일수가 부족하여 환산 비율이 불안정한 구간은 부대 평균 비율로 보정합니다. 카운트 탭에 표시되는 숫자는 실제 누적치이며, 보정 환산값은 엔진 내부 배정 평가에만 적용됩니다.

**기존 표 밥교대 변경 (부분 수정)**
[근무표 › 편집]에서 당일 또는 다음날 밥교대를 변경할 경우 전체 재생성을 수행하지 않고, 신규 밥교대자가 규칙상 수행할 수 없는 슬롯만 대체 인원으로 교체합니다 (다음날 밥교대: 당일 야간, 16:30, 17:00 순찰 / 당일 밥교대: 주간, 야간, 순찰 슬롯). 대체 인원은 엔진 검증 조건을 충족해야 하며, 필요 시 1회 맞교환을 수행합니다. 변경 대상 슬롯 목록을 확인한 후 적용할 수 있습니다.

**내 근무 (구성원 전용 화면)**
Firebase 서버가 연동된 환경에서 하단에 [내 근무] 탭이 활성화됩니다.
비로그인 상태에서는 로그인/회원가입 화면이 표시됩니다 (가입: 이메일/비밀번호 → 부대 코드 인증 → 본인 이름 지정).
로그인 후 접속 시 개인 홈 화면으로 즉시 연결됩니다.
화면 구성: 이름 및 수신 상태(서버 수신 시각) → 다음 CCTV 근무(일자, 시간, 형태, 잔여 시간, 인접 교대자) → 오늘 근무(새벽 슬롯 포함) → 최근 확인 이후 변경된 근무 → 익일 및 주간 일정(개인 달력) → 통계(최근 4주/전체) 및 배정 기준.
- 근무표 날짜(06:30~익일 05:30)와 실제 달력 날짜를 구분 표시합니다 (00:30~05:30은 익일 새벽). 번초 근무는 2개 슬롯으로 분할되나 1회 근무로 집계됩니다.
- 상태 표기: '배정된 CCTV 근무 없음'(표는 생성됨), '근무표 미생성'(표 미존재), '마지막으로 받은 근무표'(오프라인 또는 최신 동기화 대기).
- **변경된 내 근무**: 최종 확인 시점의 개인 일정(어제~13일 후)과 현재 상태를 대조하여 신규 배정, 취소, 번초 및 역할 변경 사항을 안내합니다.
  최초 접속 시점의 일정을 기준점으로 등록하며, [확인했어요] 클릭 시 현재 확인된 범위까지 기준점을 갱신합니다.
  단순 날짜 경과나 재출력에 따른 변경은 집계하지 않으며, 서버 연결 미확인 상태에서 사라진 표는 배정 취소로 간주하지 않습니다.
  확인 상태는 계정별 Firestore `personal/{uid}` 경로에 본인 전용으로 보관됩니다. 근무표 원본(`roster`) 데이터는 수정되지 않습니다.
- 통계의 '최근 4주'는 해당 구간의 근무표만으로 분자·분모를 재산출합니다 (`buildStats(null, {from, to})`).

**당직사관 · 당직사령 기록**
관리자는 [근무자 관리]에서 사관/사령 후보 명단만 관리하며(근무 자동 편성 미반영), 실제 일자별 근무 기록은 구성원이 해당 명단에서 선택하여 등록합니다.
기록은 Firestore `officerLog/{날짜}` 경로에 실시간 저장되며, 내 근무, 달력 상세, 근무표 확인 화면에 기록자 정보와 함께 표시됩니다.

**배정 이유 확인**
근무표의 각 슬롯, 역할 카드, [내 근무] 항목을 클릭하면 해당 인원이 선발된 사유가 상세 표시됩니다 (`explainAssignment`).
완성된 근무표와 이전 누적 기록을 바탕으로 후보 제외 사유(열외, 역할, 전날 야간, 연속근무 제한) 및 우선순위 결정 요인(일일 배정 수 → 시간대 공정성 → 신병 기준 → 배정률 및 평균 시간 → 최종 수행일)을 분석하여 차순위 후보와의 차이점을 안내합니다.

**전역일 계산기 및 복무율**
관리자가 [근무자 관리]에서 입대일을 입력하면 전역일(입대일 + 18개월 - 1일)이 자동 계산됩니다 (총 복무일수: 입대일 및 전역일 포함 546일 기준).
구성원은 하단 [전역] 탭([더보기 › 전역일 계산기])에서 다음 기능을 이용할 수 있습니다:
① 실시간 복무율 (소수점 7자리 갱신, D-Day, 복무 일수, 입대/전역일)
② 임의 입대일 기준 전역일 계산기
③ 부대원 복무율 순위 (실시간 순위표, 본인 강조 표시)
④ **전역까지 남은 근무 예측**: 기편성 표의 확정 근무 + 미편성 잔여일 대상 최근 8주 비율 기반 예상 근무시간, 야간 번초, 06:30, 밥교대 횟수 산출 (`remainingForecast`)
⑤ **내 근무 잔디 (히트맵)**: 입대월부터 전역월까지 일별 근무 강도 색상, 야간/휴가/미편성 상태 시각화 (`workHeatmap`)
⑥ **부대 통계**: 부대 평균 복무율, 잔여 복무일 합계, 월별 전역 타임라인 및 순위

**사람별 근무 시간 집계**
근무표 확인/편집 화면 하단에 당일 할당된 시간(07:30, 17:30, 17:00 순찰 가중치 포함)별로 인원 현황을 정렬 표시합니다.
이름 옆 수치는 전일까지의 일일 평균 근무시간이며, 부대 평균 초과 시 주황색, 미만 시 초록색으로 구분됩니다. 편집 중 수정 사항이 실시간 연동되며 시간이 변경된 인원은 점선 표시됩니다 (`schedHoursByWorker`).

**근무표 편집**
확인 화면과 동일한 레이아웃에서 [변경] 버튼을 통해 각 슬롯 인원을 수동 교체할 수 있습니다.
교체 대상 인원 선택 시 발생 가능한 제약 위반 경고가 사전에 표시됩니다.
야간 번초는 2개 슬롯이 동시에 변경됩니다. 수정된 슬롯은 '기존: 이름' 형태로 구분 표시되며, [변경사항 저장] 클릭 시 일괄 확정됩니다.

## 데이터 관리

- 로컬 저장소: localStorage 키 `cctv_roster_v2`
- 백업 및 복원: [더보기 › 백업 · 내보내기]에서 JSON 파일 내보내기/불러오기 지원 (구버전 스키마 자동 마이그레이션)
- 화면 테마: 시스템 설정을 기본으로 따르며, [더보기 › 화면]에서 다크/라이트 모드 고정 가능 (`cctv_theme_v1`)
- 사전등록(휴가, 열외, 당직/상황 예약) 및 휴무일 설정은 **근무표 생성 시점에만 적용**됩니다. 기생성된 표에는 소급 반영되지 않으며 달력 및 근무표에 `사전등록 충돌` 경고로 표시됩니다.
- 달력 표시 모드: 근무 상태(표 있음, 미생성, 확인 N건), 휴가·열외 현황, 개인 근무 현황 전환 지원

## 서버 동기화 (선택 기능)

Firebase를 연동하면 **관리자 전용 편집 및 전 부대원 실시간 열람 구조**로 전환됩니다.

- 관리자: 로그인 후 근무표 저장 시 서버 자동 업로드
- 구성원: 부대 코드로 가입 후 본인 이름 연결 → 읽기 전용 모드 + 실시간 수신 + [내 근무] 탭 활성화
- 권한 제어: Firestore 보안 규칙을 통해 서버 레벨에서 읽기/쓰기 권한 강제
- 상세 설정 방법은 [FIREBASE_SETUP.md](FIREBASE_SETUP.md)를 참조하십시오.
- **버전 보호**: 구버전 앱이 최신 스키마 데이터를 덮어쓰지 않도록 앱 버전 기반 업로드 차단 기능이 내장되어 있습니다.
- **서버 백업**: 근무표 생성 시 전체 데이터가 Firestore `backups/{id}`에 자동 백업되며(최근 10회 보관), 관리자가 특정 시점으로 즉시 복원할 수 있습니다.

## 개발 참고 사항

- `engine.js`와 `index.html` 스크립트는 동일한 전역 스코프(`DB` 등)를 공유합니다.
- 통계(`buildStats`)와 검증(`validateScheduleCached`) 결과는 메모리에 캐싱되며, 데이터 변경(`save()`, `invalidateStats()`) 시 갱신됩니다.
