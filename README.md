# CCTV 근무표 자동배정

부대 CCTV 근무표를 자동으로 편성하는 오프라인 웹앱입니다. 서버 없이 동작하며,
모든 데이터는 브라우저 localStorage에 저장됩니다.

## 실행

`index.html`을 브라우저로 열면 됩니다 (`engine.js`가 같은 폴더에 있어야 합니다).
별도 빌드·설치 과정이 없습니다.

## 앱으로 설치 (PWA)

설치형 웹앱(PWA)이라 휴대폰·PC 홈 화면/시작 메뉴에 앱처럼 추가할 수 있습니다.

- **조건**: `http://` 또는 `https://`(또는 `localhost`)로 접속해야 합니다.
  `file://`로 열면 설치·오프라인 캐시가 동작하지 않습니다. 간단히는 폴더에서
  `python3 -m http.server` 후 표시되는 주소로 접속하세요.
- **설치 방법**
  - Android/Chrome·Edge: 주소창의 *설치* 아이콘 또는 메뉴 → *앱 설치 / 홈 화면에 추가*
  - iOS/Safari: 공유 → *홈 화면에 추가*
  - 데스크톱 Chrome·Edge: 주소창 오른쪽 *설치* 아이콘
- **오프라인**: 한 번 열어두면 서비스 워커(`sw.js`)가 앱 셸을 캐시해 인터넷 없이도
  실행됩니다. 온라인일 때는 항상 최신본을 받아옵니다(network-first).
- 아이콘·이름·색상은 `manifest.webmanifest`에서 정의합니다.

## 파일 구조

| 파일 | 역할 |
|---|---|
| `index.html` | 화면(UI)·localStorage 저장/불러오기. DOM을 만지는 코드는 전부 여기에 있습니다. |
| `engine.js` | 배정 엔진·통계·검증. DOM에 의존하지 않아 Node에서 `require()`로 불러와 테스트할 수 있습니다. |
| `sync.js` | 서버 동기화(선택, Firebase). 관리자만 수정, 구성원은 실시간 열람 전용. |
| `firebase-config.sample.js` | 동기화 자동 설정 견본 — `firebase-config.js`로 복사해 사용 |
| `FIREBASE_SETUP.md` | 동기화 설정 가이드 (프로젝트 생성 → 계정 → 보안 규칙 → 연결) |
| `manifest.webmanifest` | PWA 매니페스트(앱 이름·색상·아이콘). 홈 화면 설치 정보. |
| `sw.js` | 서비스 워커. 앱 셸 캐시로 오프라인 실행·설치 지원. |
| `icon.svg` / `icon-*.png` | 앱 아이콘(원본 SVG + 192/512 일반·maskable, apple-touch, favicon). |
| `test/engine.test.js` | 엔진 회귀 테스트 (`node --test`) |

## 시간 구조

- 하루 = 06:30 ~ 익일 05:30, 1시간 24슬롯
- 주간: 06:30~16:30 (11슬롯)
- 저녁 고정: 17:30=다음날 밥교대(+순찰) · 18:30=다음날 상황병 · 19:30=다음날 당직 ·
  20:30=전날 상황병 · 21:30=전날 당직 · 14:30=평일 당일 상황병
- 야간 번초 4개 (각 4시간 간격 2슬롯): 1번초 22:30+02:30 · 2번초 23:30+03:30 ·
  3번초 00:30+04:30 · 4번초 01:30+05:30
- 17:00 추가 순찰: 2인 1조 중 '순찰만' 도는 1명 (0.5h 가산)

## 배정 규칙

**하드 제약 (절대 완화 안 됨)**
- 인접(연속) 슬롯 근무 금지 — 고정 슬롯 포함
- 전날 야간자의 아침(06:30/07:30/08:30) 근무 금지
- 같은 날 야간 번초 2개(이중 야간) 금지
- 열외자(주간/야간/전체/시간대)는 해당 영역에 배정 금지

**시간대 열외** — [생성] 탭에서 하루짜리로 사람마다 시간대를 골라 뺄 수 있습니다.
밴드는 **아침 06:30~08:30 · 오전 09:30~11:30 · 오후 12:30~16:30 · 야간 1~4번초** 네 개이며,
‘세부’를 펼치면 주간 11칸·번초 4개를 하나씩 지정할 수 있습니다. 저녁(17:30~21:30)은 역할
고정이라 열외 대상이 아닙니다.

- **밥교대**: 밥교대 근무시간(07:00~08:30 · 13:00~15:00 · 17:00~18:30)과 겹치는 칸이 하나라도
  열외면 후보에서 빠집니다 — 아침·오후 열외는 제외, **오전(09:30~11:30)만 열외면 밥교대 가능**.
- **17:00 순찰**: 순찰이 걸리는 16:30 칸이 열외일 때만 제외됩니다.
- **분모**: 부분 열외는 그날 분모(겪은 근무표 수)에 그대로 남습니다. 종일 열외일 때만
  ‘분모에서 제외’를 켤 수 있고, 이게 기존 ‘모두 열외’와 같습니다.
- 부분 열외자는 분모에 남으므로 그 시간대 배정률이 낮아져 다음에 우선 배정됩니다(의도된 보정).
- 저장은 `dayEx`(주간 전체)·`nightEx`(야간 전체)·`bothEx`(종일+분모제외)·`slotEx`(부분)로 나뉩니다.
  [달력 · 일정] 사전등록과 기간 일괄 생성은 종전대로 주간/모두 열외만 다룹니다.

**유조차 운전병(정)** — 그 주 월~일이 CCTV 근무에서 열외되지만, 완전 열외는 아닙니다.
금요일 야간 번초 1개 · 토·일과 **휴일**(공휴일·지정 휴무일·직장 휴무일, 평일이어도) 12:30 이후 1칸을 섭니다
(각각 그 사람이 가장 적게 선 번초·시간대로 자동 선택. 휴일인 금요일은 야간 대신 오후 1칸). **이 날들은 분모에 들어가지 않으므로
평균 근무시간과 배정률만 올라갑니다** — 유조차 운행에 대한 보상입니다. 그날 당직·상황병
역할이 걸려 있으면 종전대로 역할 근무를 그대로 섭니다. 대체자(부)는 완전 열외 유지입니다.
[근무표 생성]의 열외에서는 유조차 운전병이 요일별 실제 규칙대로 보입니다 — 평일(월~목) 종일, 금 야간 번초 외 전부,
토·일·휴일 12:30~16:30 외 전부가(‘직장 휴무일’ 체크를 바꾸면 바로 다시 맞춤) **잠긴 열외**(분모 제외 7일 고정)이고, 열려 있는 칸 안에서 못 서는 칸을 추가로
고르면 그 칸은 유조차 자동 배정에서도 빠집니다(시간대 열외로 저장).

**완화 사다리** — 인원이 부족하면 단계적으로 완화합니다.
1. tier 1: 제약 위반 없음 (같은 날 1인 1슬롯)
2. tier 2: 같은 날 중복 투입 허용
3. tier 3: 야간 이틀 연속 허용
4. tier 4: 야간 3일 연속 허용 (인원이 정말 없어 야간칸이 빌 때만 최후로)
5. tier 5: 부분 채움 — 그래도 못 채우면 하드 제약을 지키는 선에서 비워둠(미배정)

**공정성** — 누적 평균시간·그룹/슬롯/번초/야간/밥교대/순찰 배정률을 가중합한 점수가
낮은 사람부터 배정합니다([더보기 › 기본 설정]에서 가중치 조정 가능). 주간 시간대는 **오늘과 같은
그룹(월화목/수/금/토일)에서 그 시간대에 들어간 비율**이 낮은 사람부터 들어갑니다 —
통계 탭의 그룹별 슬롯 배정률이 그대로 배정 기준입니다. 백트래킹(MRV)으로 완전해를
찾은 뒤 1-opt(한 칸 교체)와 2-opt(두 칸 맞교환) 국소 개선을 돌립니다.
신병은 하루 2개 기본 배정으로 비교됩니다.

**06:30 순번제** — 06:30은 점수 경쟁 없이 신병·비신병이 한 줄로 돕니다. **06:30 배정률**(06:30 횟수 ÷ 근무에
포함된 날)이 가장 낮은 사람 → 동률이면 마지막 06:30이 가장 오래된 사람 순입니다. 누적 횟수가 아니라 배정률이라
전입·휴가 복귀·신병→역할 전환 직후에도 몰아 받지 않고, 이 배정률은 카운트 초기화와 무관한 전체 기록으로 셉니다.

**난수 없음** — 배정에 무작위를 쓰지 않아 같은 입력이면 항상 같은 근무표가 나옵니다. 모든 기준이 같은
동점일 때는 그 칸(번초·순찰)을 **마지막으로 선 지 가장 오래된 사람**이 먼저 들어가고(카운트 초기화와 무관한
실제 마지막 날짜 기준), 그래도 같으면 근무자 목록 순서를 따릅니다.

누적 횟수를 쓰는 항목은 **각자 분모로 나눠 공통 기준일수로 환산한 뒤** 비교합니다. 그냥
횟수로 비교하면 분모가 짧은 사람(신병→역할 전환으로 카운트를 초기화한 사람, 중도 합류자,
장기 휴가 복귀자)이 남들 누적을 따라잡을 때까지 계속 먼저 뽑혀서, 초기화로 없애준 기록만큼을
도로 갚는 꼴이 됩니다. 분모가 아주 짧으면 표본이 모자라 환산값이 요동치므로 부대 평균 비율
쪽으로 당겨 보정합니다(이력이 없는 사람은 부대 평균으로 취급). 카운트 탭에 보이는 숫자는
초기화 그대로 0부터 시작하며, 이 환산은 배정 순서에만 쓰입니다.

**밥교대 변경(이미 만든 표)** — [근무표 › 편집]에서 당일·다음날 밥교대를 바꾸면 전체를 다시 만들지 않고,
새 밥교대자가 규칙상 설 수 없게 된 칸만 다른 사람으로 바꿉니다(다음날 밥교대: 오늘 야간·16:30·17:00 순찰 /
당일 밥교대: 주간 칸·야간·순찰). 대신 설 사람은 엔진 후보 조건과 검증을 모두 통과해야 하며, 바로 넣을 사람이
없으면 한 번 맞교환합니다. 바뀌는 칸을 선택창 안에서 먼저 보여주고 [적용]을 받습니다.

**내 근무 (구성원 개인 홈)** — 서버 연결이 설정된 앱이면 하단에 [내 근무] 탭이 보이고, 로그인 전에는 로그인·가입 화면이 나옵니다
(가입: 이메일·비밀번호 → 부대 코드 → 본인 선택, 단계 사이 입력 유지, 비밀번호 표시·재설정 메일). 로그인한 구성원은
앱을 열면 인증·본인 연결을 확인한 뒤 곧바로 개인 홈으로 들어갑니다(처음 한 번만 — 실시간 갱신이 보던 탭을 바꾸지 않음).
개인 홈 순서: 이름·수신 상태(실제 서버 수신 여부와 마지막 수신 시각) → 다음 CCTV 근무(실제 날짜·시각·종류·남은 시간·앞뒤 근무자)
→ 오늘(전날 표의 새벽 근무 포함) → 지난 확인 이후 바뀐 내 근무 → 내일·이번 주(개인 달력) → 이후·지난 근무 → 통계(최근 4주/전체)·배정 기준.
- 표 날짜와 실제 날짜를 구분합니다(00:30~05:30은 그 표의 다음날 새벽). 번초 하나는 두 시각에 걸친 한 배정으로 셉니다.
- '배정된 CCTV 근무 없음'(표는 있음) · '근무표 미생성'(표 없음) · '마지막으로 받은 근무표'(서버 최신 확인 안 됨)를 구분합니다.
- **바뀐 내 근무**: 마지막으로 확인한 개인 일정(어제~13일 뒤, 내 배정 키만)과 지금을 비교해 새 배정·해제·번초·역할 변경을 보여 줍니다.
  처음엔 지금 일정을 기준으로 삼고(알림 없음), [확인했어요]를 누르면 그때 화면에 보인 범위까지만 기준을 갱신합니다.
  날짜 경과·범위 이동·재생성 시각은 변경이 아니며, 서버 최신이 확인되지 않은 동안 사라진 표는 '해제'로 보지 않습니다.
  기준은 계정별로 Firestore `personal/{uid}`(본인만 읽기·쓰기, 보안 규칙 4번)에 저장되고, 저장이 실패하면 확인 전 상태를 유지합니다.
  근무표(roster)와 관리자 save()는 건드리지 않습니다(`personalSnap`·`diffPersonal`·`ackPersonal`·`rollPersonal`).
- 통계의 '최근 4주'는 그 기간 근무표만으로 분자·분모를 함께 다시 계산합니다(`buildStats(null, {from,to})`, 공정성 탭과 같은 기준).

**당직사관 · 당직사령 기록** — 관리자는 [근무자 관리] 아래 명단만 관리하고(근무 배정에는 쓰이지 않음), 구성원이 날짜마다
그 명단에서 골라 기록합니다. 기록은 Firestore `officerLog/{날짜}`(구성원·관리자 쓰기, 공용 열람 계정은 보기)에 바로 저장되어
내 근무(오늘·내일·이번 주), 달력 날짜 상세, 근무표 확인 화면에 기록자와 함께 보입니다. 서버 연결이 없으면 표시되지 않습니다.

**배정 이유 보기** — 근무표(확인 화면·달력 상세·생성 결과)의 칸이나 역할 카드, [내 근무]의 항목을 누르면
‘왜 이 사람인지’가 나옵니다. 완성된 표와 그 날짜 이전 기록으로 엔진의 후보 조건(열외·역할·전날 야간·연속 근무 금지)과
우선순위(당일 칸 수 → 시간대 공정성 → 신병 순서 → 배정률·평균시간 → 마지막으로 선 날, 06:30은 순번제)를 다시 계산해
다음 후보와 무엇이 달랐는지, 후보가 아니었던 사람은 왜 빠졌는지 보여 줍니다(`explainAssignment`). 생성 당시의 탐색 순서까지
재현하지는 않으므로 순위가 앞선 사람이 빠졌으면 그 사실과 그 사람의 그날 근무를 그대로 알려 줍니다.

**사람별 근무 시간** — 근무표 확인·편집 화면의 시간표 아래에 사람마다 그날 받은 시간(07:30·17:30·17:00 순찰 가중 포함,
공정성 계산과 같은 기준)과 그 날짜 전까지의 하루 평균을 덜 선 사람부터 보여 줍니다. 부대 평균보다 높으면 주황, 낮으면 초록이고,
편집 중에는 고친 내용이 바로 반영되며 바뀐 사람은 기존 시간이 함께 나옵니다. 편집 선택창의 이름 옆에도 같은 숫자가 붙습니다
(`schedHoursByWorker`).

**근무표 편집** — 확인 화면과 같은 배치(역할 카드 → 주간·저녁·야간 시간순)에 [변경] 버튼만 붙습니다.
누른 칸만 아래 선택창에서 사람을 고르고, 그 사람으로 바꾸면 새로 생기는 점검 문제를 이름 아래에 보여 줍니다.
야간은 시간순으로 보이지만 변경은 번초 단위(두 시간이 함께 바뀜)입니다. 바꾼 칸은 ‘기존: 이름’으로 표시되고,
[변경사항 저장]을 누를 때 한 번에 저장됩니다(그 전에는 표·카운트에 반영되지 않음). 편집 중 날짜를 옮기거나
다른 탭으로 나가면 저장할지 묻습니다. 근무표 삭제와 tier 설명은 [배정 상세 · 근무표 관리]에 있습니다.

## 데이터

- 저장: localStorage 키 `cctv_roster_v2`
- 백업: [더보기 › 백업 · 내보내기]에서 JSON 내보내기/불러오기 (구버전 백업 자동 마이그레이션)
- 화면 테마: 기본은 기기 설정(다크/라이트)을 따르며, [더보기 › 화면]에서 이 기기만 다크·라이트로 고정할 수 있습니다(`localStorage` 키 `cctv_theme_v1`).
- 시간대 열외는 생성 탭에서 그날 하루에만 지정합니다(사전등록·일괄 생성 대상 아님).
- 사전등록(휴가·열외·당직/상황 예약)과 휴무일은 **생성 시점에만 반영**됩니다.
  이미 생성된 표에는 소급 적용되지 않으며, 대신 충돌이 달력·근무표 탭에
  `사전등록 충돌` 경고로 표시됩니다.
- 달력 탭: 날짜 칸은 표시 모드에 따라 짧은 단어만 보여 줍니다 — **근무 상태**(표 있음 · 미생성 · 확인 N),
  **휴가·열외**(휴가 N · 주간 N · 복귀 N · 열외 N · 유조차 N), **개인 근무**(선택한 사람의 당직·상황병·밥교대 · 주간 N · 저녁 N · 야간 N · 없음).
  마지막으로 쓴 모드와 근무자는 이 기기에 기억됩니다(`cctv_calmode_v1`, `cctv_calwho_v1`).
  날짜를 누르면 바로 아래에 그날의 역할·확인할 문제·휴가/열외(조건 포함)가 펼쳐지고, 시간별 근무는 필요할 때 펼칩니다.
  [한 주만 보기]로 달력을 선택한 주 한 줄로 접을 수 있습니다. 일정을 누르면 먼저 내용을 확인하고 그다음 수정·삭제합니다.

## 서버 동기화 (선택)

기본은 localStorage 단독(오프라인)이지만, Firebase를 연결하면 **관리자(행보관)만
수정하고 구성원은 실시간 열람만** 하는 구조로 동작합니다.

- 관리자: 로그인 후 저장할 때마다 자동 업로드
- 구성원: 부대 코드로 각자 가입 → 근무자 명단에서 본인 선택(근무자당 계정 1개) → 읽기 전용 화면(생성·관리 탭 숨김) + 실시간 갱신 + [내 근무] 탭,
  근무표·달력·근무 카운트·공정성 지표는 전부 열람 가능
- 권한은 Firestore **보안 규칙**(읽기=관리자·부대 코드로 등록된 구성원, 쓰기=관리자 이메일)으로 서버에서 강제
- 미설정·오프라인·로그아웃 상태에서는 기존과 완전히 동일하게 동작

설정 절차는 [FIREBASE_SETUP.md](FIREBASE_SETUP.md) 참고.

**서버 백업** — 관리자로 로그인한 상태에서 근무표를 생성할 때마다(기간 일괄 생성은 끝나고 한 번) 자동으로,
또는 [백업 · 내보내기 › 지금 서버에 백업]으로 직접
전체 데이터(JSON 내보내기와 같은 내용)를 Firestore `backups/{id}`에 올립니다. 최근 10개만 남기고
오래된 것은 자동 삭제되며, 각 백업에는 저장 시각·사유·근무자/근무표 수가 적힙니다.
[더보기 › 백업 · 내보내기]에서 내려받거나 그 시점으로 복원할 수 있습니다(복원 직전 상태도 자동 백업).
구성원 화면이 실시간 수신하는 `roster`와 분리되어 있어 구성원에게 내려가지 않습니다.

## 개발 메모

- `engine.js`와 `index.html`의 인라인 스크립트는 같은 전역 스코프를 공유합니다
  (`let DB`는 engine에서 선언, UI의 load/import가 재할당).
- 통계(`buildStats`)와 검증(`validateScheduleCached`)은 캐시되며, 저장(`save()`)
  시점에 무효화됩니다. DB를 직접 수정한 뒤에는 반드시 `save()` 또는
  `invalidateStats()`를 호출해야 합니다.
